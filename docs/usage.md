# 模块使用说明

先创建或接管一个服务器实例，再在页面顶部选择要操作的实例。文件安装、地图启停用、更新与恢复通常需要先停止游戏；游戏查询失败时，界面会显示未知或未加载状态，而不会把磁盘上存在的文件视为正在运行。

| 模块 | 用法 |
| --- | --- |
| 总览 | 查看实例状态、玩家数量、任务以及主机资源；磁盘余量低的提醒不代表所有安装都不可进行。 |
| 服务器管理 | 自动发现并接管已有目录，或安装新服务端；设置地图、模式、难度、人数与端口，执行启动、关闭与重启。 |
| Steam 工坊 | 搜索地图、选择排序与分类，或解析链接 / ID；查看详情和合集子项目后发起安装，进度在任务页查看。 |
| 已安装地图 | 上传 VPK / 含 VPK 的 ZIP、直链下载、扫描接管已有地图；查看章节、更新、启用 / 禁用、回滚与卸载。 |
| 插件与扩展 | 检查 SourceMod / MetaMod 与插件实际状态；上传 SMX 或标准目录包，启用 / 禁用或安装框架。原生框架安装需要近期验证身份。 |
| 玩家管理 | 查看在线玩家，执行踢出、封禁及公告。公告支持聊天栏、提示框和中央文字；需要对应 SourceMod Basic Chat 命令。 |
| 配置管理 | 编辑授权配置文件，先查看差异再保存；使用历史版本恢复，或保存并应用玩法配置组。 |
| 实时控制台 | 查看日志并提交 RCON 命令；命令会影响真实游戏实例，请确认当前选择的服务器。 |
| 任务与计划 | 查看下载、安装和备份的进度 / 错误，取消任务；设置定期重启、备份与地图更新检查。 |
| 备份与恢复 | 创建配置 / 插件备份或包含地图的完整备份，下载到独立位置；恢复前验证归档并创建保护备份。 |
| 维护清理 | 整理面板缓存；Linux 安装固定动作助手后可申请回收文件缓存；磁盘清理先预览、再确认允许的过期文件。不会自动清空地图或备份。 |
| 通知中心 | 汇总失败任务、可更新地图、崩溃保护与资源提醒。历史失败记录不会因为代码修复而改写成成功。 |
| 安全中心 | 查看配置检查、修改密码、重新验证敏感操作身份和管理会话。 |
| 账号与权限 | 创建 viewer、operator、maintainer、owner 账号并分配实例。所有者拥有全部实例的权限。 |
| 操作日志 | 查看管理行为、失败与权限拒绝记录，验证审计完整性。应将重要备份保存在独立位置。 |
| 系统设置 | 查看运行环境、SteamCMD 状态与 Steam API Key 配置。路径授权与公网来源通过本机环境配置管理。 |

## 工坊、上传和直链

直链必须指向公网 HTTP / HTTPS 标准端口上的实际 VPK / ZIP 文件，网页、登录页与普通网盘分享页无法直接安装。下载会验证地址及重定向，SHA256 为可选额外校验。

VPK 文件上限默认为 2 GiB。ZIP 还受文件数量、解压体积、压缩率和内容类型限制；分卷 VPK 必须保持文件与索引完整。重复 BSP 名称会触发冲突检查，不会静默覆盖另一个地图项目。

文件暂存、解压与安装按当前实际需求检查空间；安装事务还会计算需保存的旧文件。安全余量为每个磁盘 256 MiB。其他程序同时写盘时仍可能发生系统级空间不足，此时按错误与事务状态处理，不要手动删除未完成事务的回滚文件。

## 游戏公告

默认通过 SourceMod `sm_say` 与 `sm_hsay` 提交到聊天栏和提示框；也可选择中央文字。消息最长 160 个 UTF-8 字节，中文通常约 53 个字。命令成功提交不等于每位客户端都已显示或阅读，其他插件可能覆盖屏幕提示。

## 角色

viewer 只读；operator 可执行运维和玩家操作；maintainer 可管理地图、插件、配置和备份；owner 可管理账号、全局配置及维护功能。RCON 控制台本身是高权限接口，仅向可信运维人员授权。
